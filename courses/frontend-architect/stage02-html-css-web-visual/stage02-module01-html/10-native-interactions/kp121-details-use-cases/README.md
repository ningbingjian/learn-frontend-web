## 学习目标

学完本节后，你应该能够：

1. 判断 FAQ、术语说明、补充技术信息是否适合使用 `details`。
2. 理解“可折叠”不等于“所有内容都应该折叠”。
3. 避免把错误、关键价格、提交条件等重要信息藏进默认关闭区域。
4. 用内容重要性而不是视觉喜好决定是否折叠。

> **本节核心代码**：在真正的补充内容上使用 `details`。  
> **实验辅助代码**：统计哪些披露项处于打开状态。

## 理论讲解

### 1. 适合：补充信息

常见场景包括：

- FAQ 的详细回答；
- 配置项的高级说明；
- 术语解释；
- 可选的技术参数；
- 不影响主要任务完成的补充背景。

这些内容的共同点是：**用户不展开也能理解主要页面、完成主要任务。**

### 2. 不适合：完成任务必须知道的信息

例如注册前必须接受的费用、表单当前错误、危险操作后果、支付总额，不应该因为“页面更干净”就藏进默认关闭的 `details`。

如果信息直接影响用户决策，应默认可见。

### 3. FAQ 是典型场景，但也不能滥用

FAQ 很适合披露，因为用户往往只关心其中少量问题。不过核心产品政策若非常重要，仍应在相关操作附近直接展示，而不是要求用户去 FAQ 中寻找。

### 4. 语义优先于“手风琴外观”

选择 `details` 的理由应该是：

> 这里存在一个可以按需披露的附加内容单元。

而不是：

> 设计稿上看起来像一个带箭头的卡片。

## 动手编码：从 0 到 1

### 第 0 步：准备一个课程报名页

```html
<h1>前端架构课程</h1>
<p>价格：¥1999</p>
<p>报名后 7 天内可申请退款。</p>
```

**本步目标**：先放真正影响购买决策的信息。  
**为什么这样写**：价格和退款条件应直接可见。  
**运行后观察**：关键内容无需操作即可阅读。

### 第 1 步：把补充问题放进 FAQ

```html
<details>
  <summary>课程需要什么基础？</summary>
  <p>会基本 HTML、CSS 和 JavaScript 即可。</p>
</details>
```

**本步目标**：对非必读信息做按需披露。  
**为什么这样写**：用户可选择是否查看。  
**运行后观察**：FAQ 默认折叠。

### 第 2 步：加入第二个补充说明

```html
<details>
  <summary>是否提供源码？</summary>
  <p>每节都有独立案例源码。</p>
</details>
```

**本步目标**：形成典型 FAQ 列表。  
**为什么这样写**：每个问题是独立披露单元。  
**运行后观察**：两个问题可以独立展开。

### 第 3 步：观察状态但不改变核心语义

```js
const opened = [...document.querySelectorAll('details')]
  .filter(item => item.open)
  .length;
```

**本步目标**：演示脚本可以读取原生状态。  
**为什么这样写**：JS 只增强观察，不负责基础展开行为。  
**运行后观察**：状态面板显示当前展开项数量。

直接打开 `index.html`。

## 效果验证

1. 页面加载后价格、退款条件立即可见。
2. FAQ 可以独立展开和关闭。
3. 不执行 JavaScript 时 FAQ 仍然可操作。
4. 能解释为什么字段错误、支付总额等信息不该默认隐藏。
5. 能用“是否是补充内容”而不是“是否好看”来决定是否使用 `details`。
