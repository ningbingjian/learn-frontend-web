## 学习目标

学完本节后，你应该能够：

1. 使用同名 `details[name]` 创建原生互斥手风琴。
2. 理解同组最多只有一个项目处于打开状态。
3. 理解多个同组元素同时写 `open` 时，源代码顺序会影响最终打开项。
4. 知道同组元素不要求在 DOM 中紧邻。
5. 为不支持 `name` 分组的旧环境保留可用的多开回退体验。

> **本节核心代码**：多个 `<details name="faq">`。  
> **实验辅助代码**：状态列表和兼容性提示。

## 理论讲解

### 1. `name` 把多个 `details` 组成互斥组

```html
<details name="faq">
  <summary>问题 A</summary>
  <p>答案 A</p>
</details>

<details name="faq">
  <summary>问题 B</summary>
  <p>答案 B</p>
</details>
```

打开 B 时，浏览器会关闭同组中已经打开的 A。

这类“同一时刻只允许打开一个”的行为过去经常用 JS 手写，现在可以由原生 HTML 表达。

### 2. `name` 值决定分组

只有相同 `name` 值的 `details` 才属于同一组。另一个 `name="advanced"` 的披露项不会受到 `name="faq"` 的影响。

同组元素不必相邻；浏览器根据组名建立关系，而不是根据视觉位置。

### 3. 同时声明多个 `open`

如果同组多个元素在源码中都带 `open`，最终只有源代码顺序中第一个保持打开。

因此不要把“多个 open”当作状态配置方式。若要指定初始打开项，只给目标项写一个 `open`。

### 4. 兼容性回退

现代浏览器已经支持 `details[name]`。旧环境如果不识别 `name`，基础 `details/summary` 仍可工作，只是会退化为允许多个项目同时展开。

这是一种很好的渐进增强：核心内容仍然可访问。

## 动手编码：从 0 到 1

### 第 0 步：先写三个独立披露项

```html
<details>
  <summary>账户</summary>
  <p>账户相关内容。</p>
</details>
```

**本步目标**：确认基础披露可用。  
**为什么这样写**：先建立无分组基线。  
**运行后观察**：多个项目可以同时打开。

### 第 1 步：给它们相同的 `name`

```html
<details name="settings">...</details>
<details name="settings">...</details>
<details name="settings">...</details>
```

**本步目标**：启用互斥关系。  
**为什么这样写**：同名元素属于一个组。  
**运行后观察**：打开第二项会自动关闭第一项。

### 第 2 步：设置唯一初始打开项

```html
<details name="settings" open>
```

**本步目标**：定义初始状态。  
**为什么这样写**：避免多个 `open` 产生源顺序竞争。  
**运行后观察**：页面加载后只有指定项展开。

### 第 3 步：输出当前状态

```js
const state = items.map(item => `${item.id}:${item.open}`).join(' | ');
```

**本步目标**：验证原生互斥状态。  
**为什么这样写**：让 DOM 结果可见。  
**运行后观察**：同组最多一个 `true`。

## 效果验证

1. 初始只有第一项打开。
2. 打开任意其它项后，旧的打开项自动关闭。
3. 状态日志中最多出现一个 `open=true`。
4. 去掉 `name` 后可以同时展开多个项目。
5. 能解释为什么旧浏览器即使不支持 `name`，内容本身仍然可用。
