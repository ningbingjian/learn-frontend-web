## 学习目标

学完本节后，你应该能够：

1. 根据是否需要模态阻塞选择 popover 或 dialog。
2. 理解 popover 适合上下文帮助、轻量菜单和非模态浮层。
3. 理解 `dialog.showModal()` 适合确认、必须处理的任务。
4. 比较两者在焦点、背景交互和关闭方式上的差异。
5. 避免仅根据视觉“像弹窗”就选择技术元素。

> **本节核心代码**：上下文帮助用 popover，破坏性确认用 modal dialog。  
> **实验辅助代码**：背景点击计数和关闭结果。

## 理论讲解

### 1. 先问：背景是否必须不可操作？

如果答案是“否”，通常优先考虑 popover：

- 帮助气泡；
- 轻量操作菜单；
- 上下文说明；
- 可以点击外部关闭的浮层。

如果答案是“是”，并且用户必须先做出决定，则考虑：

```js
dialog.showModal();
```

### 2. Popover 不是 modal dialog

Popover 虽然进入 top layer，但页面其它内容通常仍然可以交互。`auto` 还提供 light dismiss。

因此不要用 popover 实现“必须确认才能继续”的危险操作，然后再自己拼一套遮罩和焦点限制。

### 3. Modal dialog 会使背景 inert

`showModal()` 打开后，浏览器管理模态层级与背景不可交互状态。它适合：

- 删除确认；
- 不可逆提交确认；
- 必须完成的短任务。

### 4. 焦点策略不同

Popover 通常是当前上下文的一部分，不应无理由强抢焦点。

Modal dialog 会把用户带入一个独立交互上下文，需要明确标题、初始焦点、关闭动作和关闭后的焦点恢复。

### 5. 决策表

| 问题 | 更适合 |
|---|---|
| 点击外部可关闭的帮助 | Popover |
| 非模态菜单 | Popover |
| 删除确认 | Modal dialog |
| 必须处理后才能继续 | Modal dialog |
| 简单长文补充信息 | `details` 可能更合适 |

## 动手编码：从 0 到 1

### 第 0 步：用 popover 做帮助

```html
<button popovertarget="help">什么是归档？</button>
<div id="help" popover>归档不会删除数据。</div>
```

**本步目标**：匹配轻量上下文信息。  
**为什么这样写**：无需中断主任务。  
**运行后观察**：背景仍可操作。

### 第 1 步：用 dialog 做删除确认

```html
<button id="delete">删除项目</button>
<dialog id="confirm-dialog">...</dialog>
```

**本步目标**：为不可逆动作建立独立确认流程。  
**为什么这样写**：背景应暂时不可操作。  
**运行后观察**：默认隐藏。

### 第 2 步：通过 `showModal()` 打开

```js
deleteButton.addEventListener('click', () => dialog.showModal());
```

**本步目标**：让浏览器提供模态约束。  
**为什么这样写**：不手工模拟遮罩和 inert。  
**运行后观察**：背景按钮在 modal 打开时不可操作。

### 第 3 步：对照同一个背景按钮

**本步目标**：直接比较两种控件的交互边界。  
**为什么这样写**：视觉差异不如行为差异重要。  
**运行后观察**：popover 打开时可点击背景，dialog modal 打开时不行。

## 效果验证

1. 打开帮助 popover 后仍可点击背景操作。
2. 打开删除确认 dialog 后背景不可操作。
3. popover 可 light dismiss；dialog 提供明确取消/确认按钮。
4. 能根据“是否需要模态阻塞”快速选择元素。
5. 能说明普通长文本折叠为什么可能更适合 `details` 而不是这两者。
