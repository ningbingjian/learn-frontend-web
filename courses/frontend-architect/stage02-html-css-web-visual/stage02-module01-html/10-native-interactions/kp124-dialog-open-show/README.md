## 学习目标

学完本节后，你应该能够：

1. 使用 `<dialog>` 表达原生对话框。
2. 理解 `open` 属性会让对话框以**非模态**方式直接显示。
3. 使用 `show()` 打开可重复控制的非模态对话框。
4. 使用 `close()` 正确关闭，并观察 `.open`。
5. 理解非模态对话框不会阻止用户与页面其它区域交互。

## 理论讲解

### 1. `dialog` 可以表示模态或非模态对话框

本节只讨论非模态：用户打开对话框后，仍然可以操作页面其它内容。

两种常见打开方式：

```html
<dialog open>...</dialog>
```

以及：

```js
dialog.show();
```

### 2. `open` 是初始展示手段，但通常不适合作为完整控制 API

`open` 是布尔属性。存在时对话框可见，并且是非模态。

它适合演示静态初始状态，但产品中的可重复打开/关闭更推荐调用：

```js
dialog.show();
dialog.close();
```

这样浏览器能按 `HTMLDialogElement` 的状态模型执行操作。

### 3. `show()` 是非模态

```js
dialog.show();
```

打开后页面其余部分不会变成 inert。用户可以继续点击背景按钮、输入表单或滚动页面。

如果业务需要强制用户先处理确认，则应进入下一节 `showModal()`。

### 4. 不要对已经打开的对话框重复调用不兼容方法

例如对一个已经通过 `showModal()` 打开的对话框调用 `show()` 会产生 `InvalidStateError`。反方向也同理：已经以非模态形式打开时不能直接 `showModal()`。

真实代码通常先通过 `dialog.open` 判断状态或保持清晰的单一打开路径。

## 动手编码：从 0 到 1

### 第 0 步：加入一个静态 `open` 对话框

```html
<dialog open>
  <p>这是初始可见的非模态提示。</p>
</dialog>
```

**本步目标**：观察 `open` 的直接效果。  
**为什么这样写**：建立布尔属性与可见状态的对应关系。  
**运行后观察**：页面加载后对话框已显示，背景仍能交互。

### 第 1 步：创建可控制的第二个 dialog

```html
<button id="open-profile">打开资料面板</button>
<dialog id="profile-dialog">
  <p>资料编辑内容。</p>
  <button id="close-profile">关闭</button>
</dialog>
```

**本步目标**：准备动态非模态对话框。  
**为什么这样写**：打开按钮放在 dialog 外，关闭按钮放在内部。  
**运行后观察**：默认隐藏。

### 第 2 步：用 `show()` 打开

```js
openButton.addEventListener('click', () => {
  if (!dialog.open) dialog.show();
});
```

**本步目标**：使用官方 API 打开。  
**为什么这样写**：避免重复调用导致状态异常。  
**运行后观察**：对话框出现，但背景按钮仍可点击。

### 第 3 步：用 `close()` 关闭

```js
closeButton.addEventListener('click', () => dialog.close());
```

**本步目标**：完成开关循环。  
**为什么这样写**：不直接手工操作 `display`。  
**运行后观察**：关闭后可再次打开。

## 效果验证

1. 初始 dialog 页面加载后可见。
2. 动态 dialog 可以反复 `show()` / `close()`。
3. 动态 dialog 打开时仍能点击“背景操作”按钮。
