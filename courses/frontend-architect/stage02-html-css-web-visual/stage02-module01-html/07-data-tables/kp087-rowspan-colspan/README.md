## 学习目标

完成本节后，你应该能够：

1. 使用 `rowspan` 让一个单元格占据连续多行。
2. 使用 `colspan` 让一个单元格占据连续多列。
3. 理解“源码中的第几个单元格”不等于“视觉网格中的第几列”。
4. 能根据已经被跨行单元格占用的位置推导后续单元格坐标。
5. 知道合并单元格越多，表头关系、维护成本和读屏理解成本通常越高。

## 理论讲解

### 1. rowspan 和 colspan 解决什么问题

普通表格里，每个单元格默认占据一个网格位置。

```html
<tr>
  <td>华东</td>
  <td>上海</td>
  <td>120</td>
</tr>
```

当多个相邻位置表达同一个共同含义时，可以让一个单元格跨越多个网格位置：

```html
<th rowspan="2" scope="rowgroup">华东</th>
```

表示“华东”这个表头同时覆盖接下来的两行。

```html
<th colspan="2" scope="colgroup">销售额（万元）</th>
```

表示“销售额（万元）”这个表头覆盖接下来的两列。

两个属性的值都表示占据的网格槽位数量，而不是 CSS 宽度或高度。

### 2. 跨单元格会改变后续网格坐标

这是本节最重要的地方。

看下面两行：

```html
<tr>
  <th rowspan="2">华东</th>
  <td>上海</td>
  <td>120</td>
</tr>
<tr>
  <td>杭州</td>
  <td>98</td>
</tr>
```

第二个 `<tr>` 源码里虽然第一个元素是“杭州”，但它在视觉网格里并不是第 1 列。

原因是第 1 列已经被上一行的 `rowspan="2"` 占用了。

因此第二行真正的网格是：

```text
第 1 列：华东（上一行延伸下来）
第 2 列：杭州
第 3 列：98
```

同理，`colspan="2"` 会一次占用两个连续列位置，后续单元格必须从下一个空闲列继续放置。

所以分析复杂表格时，不要只数 DOM 子元素个数，而要考虑跨行、跨列形成的实际二维网格。

### 3. 复杂度与可访问性边界

`rowspan` 和 `colspan` 并不是“让表格更高级”的装饰属性。

只有数据关系本身真的存在分组时才应该使用。

例如：

- 一个地区包含两座城市：可以考虑 `rowspan`。
- “销售额”下面分 1 月和 2 月：可以考虑 `colspan`。
- 只是为了让某个格子看起来更宽：优先使用 CSS，而不是 `colspan`。

跨单元格越多，需要理解的坐标关系越复杂。

对于简单表头，`scope` 往往足够；对于多层复杂表头，则可能还需要上一节学习的 `id` 与 `headers` 明确关联。

设计数据表格时应优先保证：

1. 数据关系清楚。
2. 表头层级有限。
3. 合并单元格数量尽可能少。
4. 使用读屏工具实际验证复杂表头关系。

## 动手编码：从 0 到 1

### 第 0 步：创建最小页面

创建 `index.html`：

```html
<!doctype html>
<html lang="zh-CN">
<head>
  <meta charset="utf-8">
  <title>KP087 rowspan 与 colspan</title>
</head>
<body>
  <h1>区域月度销售表</h1>
</body>
</html>
```

**本步目标**：先得到一个可以直接打开的最小 HTML 页面。

**运行后观察**：浏览器能够正常显示页面标题和主标题。

### 第 1 步：建立普通四列表格

先写出区域、城市、1 月、2 月四列：

```html
<table>
  <thead>
    <tr>
      <th>区域</th>
      <th>城市</th>
      <th>1 月</th>
      <th>2 月</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>华东</td>
      <td>上海</td>
      <td>120</td>
      <td>132</td>
    </tr>
    <tr>
      <td>华东</td>
      <td>杭州</td>
      <td>98</td>
      <td>105</td>
    </tr>
  </tbody>
</table>
```

**为什么这样写**：先看没有合并时的规则网格，后面才能比较坐标变化。

### 第 2 步：使用 colspan 创建两级列表头

把两个“月份”归入共同的“销售额（万元）”表头：

```html
<thead>
  <tr>
    <th rowspan="2" scope="col">区域</th>
    <th rowspan="2" scope="col">城市</th>
    <th colspan="2" scope="colgroup">销售额（万元）</th>
  </tr>
  <tr>
    <th scope="col">1 月</th>
    <th scope="col">2 月</th>
  </tr>
</thead>
```

**本步目标**：观察 `rowspan="2"` 与 `colspan="2"` 同时出现时形成的表头网格。

**运行后观察**：前两个表头纵向占两行，“销售额”横向覆盖两个月份。

### 第 3 步：使用 rowspan 合并区域

正文中让“华东”覆盖上海和杭州两行：

```html
<tbody>
  <tr>
    <th rowspan="2" scope="rowgroup">华东</th>
    <th scope="row">上海</th>
    <td>120</td>
    <td>132</td>
  </tr>
  <tr>
    <th scope="row">杭州</th>
    <td>98</td>
    <td>105</td>
  </tr>
</tbody>
```

**为什么第二行没有再写“华东”**：第 1 列已经被上一行的 `rowspan="2"` 占用。

### 第 4 步：加入另一组数据验证网格继续排列

再加入华南两行：

```html
<tr>
  <th rowspan="2" scope="rowgroup">华南</th>
  <th scope="row">广州</th>
  <td>110</td>
  <td>117</td>
</tr>
<tr>
  <th scope="row">深圳</th>
  <td>126</td>
  <td>139</td>
</tr>
```

**运行后观察**：每个区域都在第 1 列跨两行，但城市和月份数据仍应落在固定列。

### 第 5 步：加入网格坐标观察脚本

最终案例使用 JavaScript 根据 `rowSpan`、`colSpan` 计算每个单元格真正占用的二维坐标，并输出到页面。

这段 JavaScript只是实验辅助代码，不是本节 HTML 语义的组成部分。

它用于证明：

- `tr.children.length` 只表示源码当前行包含多少元素。
- 实际网格列数还必须考虑之前的 `rowspan`。
- 一个 `colspan="2"` 单元格会同时占两个横向坐标。

### 第 6 步：加入最小 CSS 方便观察

案例为表格增加边框和间距，让跨行跨列边界更容易观察。

CSS 只负责显示，不决定 `rowspan`、`colspan` 的数据关系。

## 效果验证

### 验证 1：检查 colspan

在开发者工具中选中“销售额（万元）”表头，应看到：

```html
<th colspan="2" scope="colgroup">销售额（万元）</th>
```

它占据两个月份列。

### 验证 2：检查 rowspan

选中“华东”表头，应看到：

```html
<th rowspan="2" scope="rowgroup">华东</th>
```

第二个城市所在 `<tr>` 中不应再出现一个区域单元格。

### 验证 3：观察真实坐标

页面“网格坐标观察”区域会列出每个单元格的起始行列和跨度。

重点比较“杭州”：它虽然是该 `<tr>` 的第一个 DOM 子元素，但真实起始列是第 2 列，因为第 1 列已经被“华东”占用。

### 验证 4：检查总网格宽度

表头最终应形成 4 个逻辑列：

```text
区域 | 城市 | 1 月 | 2 月
```

如果跨单元格配置错误，观察脚本输出的坐标就会出现错位。

### 验证 5：检查可访问性

使用浏览器 Accessibility 面板或读屏工具检查复杂表头。

不要因为视觉上看起来“合并正确”，就假设所有辅助技术都能自动推断复杂关系。复杂表格应结合实际目标浏览器和读屏器验证。
