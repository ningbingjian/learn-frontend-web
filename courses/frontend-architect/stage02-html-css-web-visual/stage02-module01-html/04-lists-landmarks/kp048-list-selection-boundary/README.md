## 学习目标

完成本节后，你应该能够：

1. 根据内容关系选择 `ul`、`ol`、`dl`。
2. 识别“不应该为了样式而使用列表”的场景。
3. 区分“导航区域”与“导航内部的链接列表”。
4. 在需求评审时先问“这些内容之间是什么关系”。
5. 用语义而不是 CSS 默认表现决定标签。

## 理论讲解

### 1. `ul`：同级集合

如果项目属于同一个集合，而且顺序不是重点，优先考虑 `<ul>`：

```html
<ul>
  <li>支持中文</li>
  <li>支持英文</li>
  <li>支持日文</li>
</ul>
```

交换三项顺序，内容本身没有被破坏。

### 2. `ol`：顺序具有含义

如果项目有步骤、排名、时间先后等关系，优先考虑 `<ol>`：

```html
<ol>
  <li>填写资料</li>
  <li>验证邮箱</li>
  <li>完成注册</li>
</ol>
```

这里顺序不是装饰，而是流程本身。

### 3. `dl`：名称与描述关系

如果内容是一组名称和值、术语和定义、键和说明，优先考虑 `<dl>`：

```html
<dl>
  <dt>版本</dt>
  <dd>1.0.0</dd>

  <dt>状态</dt>
  <dd>稳定</dd>
</dl>
```

### 4. 列表与普通段落的边界

下面是连续说明文字：

```html
<p>本课程从 HTML 语义开始。</p>
<p>随后进入 CSS 和 JavaScript。</p>
```

这两个段落并不是“两个待选择的项目”，也不是步骤或名称—描述关系。

因此不要为了让每段前面出现一个圆点，就强行改成 `<ul>`。

判断问题可以简化为：

```text
这是集合吗？
├── 否 → 普通正文结构
└── 是
    ├── 顺序重要 → ol
    ├── 名称-描述 → dl
    └── 其他同级集合 → ul
```

### 5. 列表与导航的边界

`<nav>` 表示导航区域。

`<ul>` 表示列表。

它们可以组合：

```html
<nav aria-label="主导航">
  <ul>
    <li><a href="/">首页</a></li>
    <li><a href="/docs">文档</a></li>
  </ul>
</nav>
```

但 `<nav>` 并不要求内部必须是 `<ul>`：

```html
<nav aria-label="上一页和下一页">
  <a href="prev.html">上一页</a>
  <a href="next.html">下一页</a>
</nav>
```

所以要分别判断两个问题：

1. 这是不是主要导航区域？
2. 导航中的链接本身是否构成列表？

## 动手编码：从 0 到 1

本节最终源码：[`index.html`](./index.html)

### 第 1 步：写一个同级功能集合

**目标**：用 `ul` 表达顺序不重要的功能项。

```html
<section>
  <h2>产品能力</h2>
  <ul>
    <li>消息通知</li>
    <li>文件上传</li>
    <li>数据导出</li>
  </ul>
</section>
```

**为什么这样写**：三项是同级能力，不构成流程。

### 第 2 步：写一个有序流程

**目标**：用 `ol` 表达步骤。

```html
<section>
  <h2>开通流程</h2>
  <ol>
    <li>创建账号</li>
    <li>验证邮箱</li>
    <li>进入控制台</li>
  </ol>
</section>
```

**为什么这样写**：步骤交换会影响流程。

### 第 3 步：写一组元数据

```html
<dl>
  <dt>套餐</dt>
  <dd>Pro</dd>
  <dt>周期</dt>
  <dd>按月</dd>
</dl>
```

**为什么这样写**：这是名称和值的关系，而不是普通同级项目。

### 第 4 步：保留普通段落

```html
<p>列表标签不是为了产生缩进、圆点或编号。</p>
<p>当内容本质是正文，就继续使用段落。</p>
```

**运行后观察**：段落没有列表语义。

### 第 5 步：加入导航组合示例

```html
<nav aria-label="课程章节">
  <ul>
    <li><a href="#features">产品能力</a></li>
    <li><a href="#steps">开通流程</a></li>
  </ul>
</nav>
```

**为什么这样写**：`nav` 表示区域用途，`ul` 表示导航链接组成列表，两层语义各司其职。

### 第 6 步：用脚本输出页面使用的语义结构

```js
const tags = ['ul', 'ol', 'dl', 'nav', 'p'];
```

统计每类元素数量，帮助验证选择结果。
