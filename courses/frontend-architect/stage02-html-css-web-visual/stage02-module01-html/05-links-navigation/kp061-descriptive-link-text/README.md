## 学习目标

完成本节后，你应该能够：

1. 识别“点击这里”“更多”“详情”这类弱链接文本的问题。
2. 编写能表达目标或动作的可理解链接文本。
3. 理解用户可能通过链接列表、读屏快捷键或页面搜索脱离原段落浏览链接。
4. 理解可访问名称不一定等于肉眼看到的可见文本。
5. 避免多个不同目标都使用完全相同、缺乏上下文的链接名称。
6. 知道什么时候不应该滥用 `aria-label` 覆盖可见链接文本。

## 理论讲解

### 1. 链接文本要说明目的

不推荐：

```html
<p>
  我们发布了新的 HTML 表单指南，
  <a href="/guides/forms">点击这里</a>查看。
</p>
```

问题在于：

```text
点击这里
```

并没有告诉用户目标是什么。

更清晰的写法：

```html
<a href="/guides/forms">查看 HTML 表单指南</a>
```

或者把自然语言直接做成链接：

```html
<p>
  阅读<a href="/guides/forms">HTML 表单指南</a>，了解原生校验与错误提示。
</p>
```

链接文本应该优先表达：

- 要去哪里；
- 要打开什么资源；
- 要执行什么动作。

例如：

```text
下载 2026 前端学习路线 PDF
查看 Pro 套餐价格
阅读 HTML 表单校验指南
打开订单详情
```

这些都比单独的“这里”“更多”“查看”信息更完整。

### 2. 脱离上下文仍要尽量可理解

链接并不总是按照视觉段落顺序被消费。

例如一些用户会：

- 使用读屏软件的“链接列表”；
- 使用快捷键在链接之间跳转；
- 通过浏览器搜索寻找某个链接名称；
- 快速扫描页面中的可点击文本。

如果页面存在：

```html
<a href="#html">详情</a>
<a href="#css">详情</a>
<a href="#js">详情</a>
```

脱离周围卡片标题后，只剩下三个“详情”，用户很难判断每个链接分别去哪里。

更合适：

```html
<a href="#html">查看 HTML 课程详情</a>
<a href="#css">查看 CSS 课程详情</a>
<a href="#js">查看 JavaScript 课程详情</a>
```

这并不意味着链接文本必须非常长。

如果页面上下文已经非常明确，也可以适度简洁，但应避免让关键意义只能依赖视觉位置推断。

### 3. 可访问名称与重复链接

链接的“可访问名称”是辅助技术用来识别这个链接的名称。

最简单、最稳定的情况通常是可见文本本身：

```html
<a href="#pricing">查看 Pro 套餐价格</a>
```

有时开发者会写：

```html
<a href="#pricing" aria-label="查看 Pro 套餐价格">
  查看价格
</a>
```

`aria-label` 可以提供或覆盖可访问名称，但不应该被当成“所有链接都必须加”的属性。

原因包括：

- 可见文本和可访问名称不一致时，用户可能得到不同信息；
- 语音控制用户通常依赖屏幕上看到的文字发出命令；
- 能直接把可见文本写清楚时，通常没有必要额外覆盖。

优先策略：

```text
先把真实可见链接文本写清楚
→ 只有确实需要时再考虑 aria-label / aria-labelledby
```

对于“相同名称、相同目标”的重复链接，例如页面顶部和底部都出现：

```text
返回首页
```

通常问题不大。

真正需要警惕的是：

```text
三个“详情”
→ 分别指向三个完全不同内容
```

## 动手编码：从 0 到 1

本节最终源码：[`index.html`](./index.html)

### 第 1 步：创建三个课程卡片

**目标**：构造常见的列表卡片场景。

```html
<article>
  <h2>HTML 语义化</h2>
  <p>学习文本、列表、表单和页面地标。</p>
  <a href="#html-course">详情</a>
</article>
```

再创建 CSS 和 JavaScript 两个卡片。

**为什么这样写**：卡片里的“详情”视觉上似乎能靠标题判断，但脱离卡片上下文后信息不足。

**运行后观察**：页面出现三个都叫“详情”的链接。

### 第 2 步：把链接文本改为自描述文本

**目标**：让链接名称自身表达目的。

```html
<a href="#html-course">查看 HTML 语义化课程详情</a>
```

另外两项改为：

```text
查看 CSS 布局课程详情
查看 JavaScript 基础课程详情
```

**为什么这样写**：即使只看到链接文本，也能知道每个链接的目标。

**运行后观察**：三个链接名称不再依赖卡片标题才能区分。

### 第 3 步：增加可访问名称对照

**目标**：观察 `aria-label` 会提供另一层名称信息。

```html
<a id="short-link"
   href="#pricing"
   aria-label="查看 Pro 套餐价格">
  查看价格
</a>
```

**为什么这样写**：这个例子用于说明可见文本和 ARIA 名称可能不同，不代表推荐所有链接都这样写。

**运行后观察**：屏幕显示“查看价格”，DOM 中同时存在更具体的 `aria-label`。

### 第 4 步：打印链接摘要

**目标**：模拟“脱离正文只看链接列表”的体验。

```js
const links = [...document.querySelectorAll('a[data-demo]')];

const lines = links.map((link) => {
  const visibleText = link.textContent.trim();
  const ariaLabel = link.getAttribute('aria-label');
  return `${visibleText} -> ${link.getAttribute('href')} | aria-label: ${ariaLabel ?? '(none)'}`;
});
```

**为什么这样写**：JavaScript 不计算完整 Accessibility API 名称算法，只负责把本案例中最关键的文本、目标和 `aria-label` 并列展示。

**运行后观察**：三个课程链接即使单独列出，也能清楚区分目标。

## 效果验证

完成案例后检查：

1. 三个课程链接都包含具体课程名称。
2. 单独看链接列表也能区分三个目标。
3. 页面没有把“点击这里”作为主要链接名称。
4. `#short-link` 的可见文字与 `aria-label` 不同，能解释两者差异。
5. 能说明为什么不应该为了“无障碍”机械地给所有链接加 `aria-label`。
6. 能判断“相同文本 + 不同目标”的重复链接是否需要改进。
