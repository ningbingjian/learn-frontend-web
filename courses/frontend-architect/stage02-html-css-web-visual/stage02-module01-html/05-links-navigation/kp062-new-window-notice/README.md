## 学习目标

完成本节后，你应该能够：

1. 解释为什么链接打开新窗口 / 新标签页时应该让用户提前知道。
2. 使用可见文本把“在新窗口打开”纳入链接名称或邻近说明。
3. 理解 `target="_blank"` 只表达打开新的浏览上下文，不保证一定是“标签页”还是“独立窗口”。
4. 从键盘和读屏用户角度理解上下文变化的影响。
5. 判断哪些场景没有必要强制新开窗口。
6. 知道本节重点是“行为预期”，`target` 与 `rel` 的技术细节会在后续知识点继续展开。

## 理论讲解

### 1. 为什么新窗口需要提示

普通链接通常给用户一种预期：

```text
点击链接
→ 当前页面导航到新位置
```

如果页面突然把链接打开到新的浏览上下文，用户可能遇到：

- 当前页面仍留在原位置；
- 浏览器新增标签页或窗口；
- 后退按钮行为与预想不同；
- 焦点进入新的浏览上下文；
- 关闭新页面后需要重新定位原页面。

因此，如果产品确实决定新开浏览上下文，应在点击前提示。

不推荐只写：

```html
<a href="https://example.com/report" target="_blank">
  查看年度报告
</a>
```

用户看不到任何行为提示。

更清晰的写法：

```html
<a href="https://example.com/report"
   target="_blank"
   rel="noopener">
  查看年度报告（在新窗口打开）
</a>
```

这里“新窗口”是用户层面的概括。实际是新标签页还是独立窗口，由：

- 浏览器；
- 用户设置；
- 平台策略；

共同决定。

### 2. 键盘和读屏体验

对于鼠标用户，新标签页可能很容易被视觉发现。

但对于键盘或读屏用户，关键问题是：

```text
浏览上下文已经改变了吗？
```

如果链接名称本身包含：

```text
（在新窗口打开）
```

读屏软件在读取链接名称时就有机会把这个预期一起传达。

例如：

```html
<a href="https://example.com/help"
   target="_blank"
   rel="noopener">
  打开外部帮助中心（在新窗口打开）
</a>
```

如果设计使用图标提示，也要确保信息不只存在于纯视觉图标里。

例如可以写：

```html
<a href="..." target="_blank" rel="noopener">
  外部帮助中心
  <span class="new-window-note">（在新窗口打开）</span>
</a>
```

然后再通过 CSS 决定展示形式。

不要假设：

```text
有一个“↗”图标
= 所有用户都知道它代表新窗口
```

图标可以作为补充，但关键行为提示需要可理解。

### 3. 产品场景取舍

新窗口并不是“外链的默认正确答案”。

很多时候直接使用普通链接更简单：

```html
<a href="https://example.com/docs">
  查看外部文档
</a>
```

用户仍可以自己通过：

- Ctrl / Command + 点击；
- 鼠标中键；
- 右键菜单；

决定是否新开标签页。

产品真正需要强制新开的常见考虑可能包括：

- 当前页面是长流程，产品明确希望保留现场；
- 某些工具、预览或外部系统需要独立上下文；
- 业务流程经过测试后确认新开更合适。

但也要评估代价：

- 增加认知负担；
- 移动端标签管理更麻烦；
- 键盘用户需要理解上下文变化；
- 用户失去“当前页直接前进 / 后退”的简单模型。

因此推荐决策顺序：

```text
能在当前上下文打开吗？
→ 如果可以，优先普通链接
→ 如果确实必须新开，再明确告知
```

本节案例会同时展示：

- 普通当前上下文链接；
- 带明确提示的新窗口链接；
- 只写 `_blank` 但没有提示的反例。

## 动手编码：从 0 到 1

本节最终源码：[`index.html`](./index.html)

### 第 1 步：创建普通链接

**目标**：先建立默认导航预期。

```html
<a data-demo href="#normal-target">
  查看本页说明
</a>
```

**为什么这样写**：普通链接是最基础的对照组，用户可以预期当前上下文导航。

**运行后观察**：点击后页面跳到当前文档中的目标。

### 第 2 步：增加新窗口链接并写出提示

**目标**：让行为变化在点击前可感知。

```html
<a data-demo
   href="https://example.com/report"
   target="_blank"
   rel="noopener">
  查看示例年度报告（在新窗口打开）
</a>
```

**为什么这样写**：`target="_blank"` 改变浏览上下文，文字提示负责告诉用户这一变化。

**运行后观察**：浏览器通常会新开标签页或窗口；具体形式由浏览器和用户设置决定。

### 第 3 步：加入反例

**目标**：对比“行为变了但文本没提示”的问题。

```html
<a data-demo
   href="https://example.com/help"
   target="_blank"
   rel="noopener">
  打开帮助中心
</a>
```

**为什么这样写**：这是教学反例，用来说明 `_blank` 本身不会自动给可见文本加行为说明。

**运行后观察**：肉眼只看链接文本时，看不出它与普通链接行为不同。

### 第 4 步：输出链接行为摘要

**目标**：把 `target` 和可见提示并列展示。

```js
const links = [...document.querySelectorAll('a[data-demo]')];

const lines = links.map((link) => {
  const text = link.textContent.trim();
  const target = link.getAttribute('target') ?? '_self';
  const hasNotice = /新窗口|新标签/.test(text);

  return `${text} | target=${target} | visible notice=${hasNotice}`;
});
```

**为什么这样写**：JavaScript 只用于教学检查，不自动修改链接。

**运行后观察**：带 `_blank` 的两个链接里，只有一个文本包含明确提示。

完成案例后检查：
