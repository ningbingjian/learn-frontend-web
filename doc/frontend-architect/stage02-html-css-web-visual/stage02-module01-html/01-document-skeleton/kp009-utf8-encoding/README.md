## 理论讲解

### 1. 字符与字节

字符是人看到的文字，字节是文件和网络中传输的数据。编码负责把字符转换成字节，解码负责把字节还原成字符。同一个字符在不同编码下可能对应不同字节序列。

### 2. UTF-8 声明与真实文件编码

HTML 使用下面的声明：

```html
<meta charset="utf-8">
```

声明应尽早出现在 `head` 中，文件本身也必须真正保存为 UTF-8。通过 HTTP 访问时，响应头中的 charset 同样需要保持一致。`meta charset` 只声明解码方式，不会自动转换错误字节。

### 3. 多语言文本与字节观察

UTF-8 可以统一表示中文、拉丁扩展字符、货币符号、Emoji 和阿拉伯文。浏览器中的 `TextEncoder` 可以把字符串编码为 UTF-8 字节，帮助区分“看到的字符”和“实际字节”。

## 源码讲解

[`index.html`](./index.html) 在 `head` 中声明 UTF-8，并展示多类字符。脚本把“中文”交给 `TextEncoder`，再把每个字节转换成两位十六进制文本。

最终输出把原始字符和字节放在同一行，建立“字符 → UTF-8 字节”的对应关系。

## 运行案例

使用浏览器打开 [`index.html`](./index.html)，确认所有字符正常显示并查看字节输出。可以把脚本中的字符串替换为其他中文、Emoji 或带重音字符，再保存刷新。

通过本地服务器运行时，在当前目录执行 `python3 -m http.server 8080`，并可在 Network 面板检查 `Content-Type`。

## 效果验证

- 中文、`café`、货币符号、Emoji 和阿拉伯文应正确显示。
- “中文”的 UTF-8 字节应为 `e4 b8 ad e6 96 87`。
- 修改原始字符串后，页面显示字符和输出字节应同时变化。
- 若字体出现方框但字符串码点正确，应继续检查字体，而不是直接判定编码错误。
