## 理论讲解

### 1. 解析器会自动纠错

HTML 解析不是简单地按照缩进把字符串转换成 DOM。浏览器会根据当前解析状态、元素内容模型和错误恢复规则补充、关闭或移动节点。

### 2. 段落的隐式结束

`p` 只能包含适合段落的短语内容。当解析器在 `p` 内遇到 `div` 等区块元素时，会先隐式结束段落：

```html
<p id="intro">
  商品介绍
  <div id="card">商品卡片</div>
</p>
```

虽然源码缩进看起来像父子关系，但解析后的 `card` 并不位于 `intro` 中。

### 3. 源码与 DOM 的对照方法

“查看源代码”看到服务器返回的文本，Elements 面板和 DOM API 看到浏览器解析后的树。CSS 选择器和 JavaScript 查询都基于后者，因此结构问题必须检查真实 DOM。

## 源码讲解

[`index.html`](./index.html) 故意把 `div#card` 写进 `p#intro`。脚本检查 `intro.contains(card)`、`card.parentElement`，并列出 `body` 的直接子元素。

这三个输出分别回答“是否仍为父子关系”“卡片实际属于谁”“解析器最终生成了哪些顶层结构”。

## 运行案例

先阅读 [`index.html`](./index.html) 并预测 DOM，再使用浏览器打开页面。查看输出和 Elements 面板后，把错误结构改成 `p + div + p`，保存并刷新。

通过本地服务器运行时，在当前目录执行 `python3 -m http.server 8080`。

## 效果验证

错误结构中应观察到：

- `intro.contains(card)` 为 `false`。
- `card` 的实际父元素为 `body`。
- Elements 面板中的结构与源码缩进不同。

改成合法的 `p + div + p` 后，源码结构与解析后 DOM 应保持一致。
